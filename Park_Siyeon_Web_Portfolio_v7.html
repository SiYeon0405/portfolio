무엇을 만들었는지

창업 아이디어의 고객·가격·시장 가정을 인터뷰로 확인하고, 사용자가 다음에 조사할 내용을 리포트로 정리하는 캡스톤 팀 프로젝트입니다. FastAPI에서 맞춤 질문과 리포트 생성 흐름을 개발하고, PostgreSQL과 pgvector를 사용해 논문 근거 검색을 연결했습니다.

데이터 흐름과 기술 스택

  1. 창업 아이디어 입력
  2. LLM 인터뷰
  3. 논문 근거 검색
  4. 인용 연결 · 리포트 저장

Python · FastAPI · SQLAlchemy · Supabase PostgreSQL · pgvector를 사용했습니다. 인터뷰 답변을 바탕으로 검색 질의를 구성하고, 저장된 논문 본문 조각을 검색해 리포트 생성에 사용했습니다.

제가 맡은 백엔드 구현

인터뷰의 질문 생성·저장 흐름, 중복 질문 차단, 리포트 생성과 인용 연결을 개발했습니다. 사용자가 답한 고객·가격·시장 정보를 후속 질문과 리포트에 전달하도록 구성했습니다.

RAG 리포트 구현

  1. 검색 질의 구성 인터뷰 내용으로 리포트에 필요한 근거를 찾을 질의를 만들고, pgvector에서 논문 본문 조각을 의미가 가까운 순서로 검색했습니다.
  2. 근거와 리포트 연결 검색된 조각에 근거 ID를 붙여 모델에 전달했습니다. 모델이 반환한 인용 ID가 해당 검색에서 가져온 ID인지 확인하고, 유효한 인용을 리포트 섹션과 연결해 저장했습니다.
  3. 검색 방식 확장 별도 검색 경로에서 pgvector 의미 검색과 BM25 키워드 검색을 실행하고, 두 결과의 순위를 RRF로 합쳤습니다.

근거 연결 검증

논문 발췌문과 그 내용을 직접 뒷받침하는 주장을 고정 입력으로 넣어, 검색 기록에서 발급한 인용 ID가 검증을 거쳐 리포트에 보존되는지 확인했습니다. 이 실험은 인용 연결을 확인한 테스트입니다. 실제 검색의 관련성과 주장 검증 정확도는 추가 평가가 필요합니다.

인터뷰 속도와 질문 품질

창업 아이디어에 맞춰 질문을 만드는 과정이 길었습니다. 가격 답변을 고객 정보의 모순으로 해석해 이미 답한 고객 질문을 다시 묻는 사례도 있었습니다.

문제와 맡은 일

유치원 교사가 동화를 수업에 활용할 때 어떤 누리과정 영역과 연결할 수 있는지 참고할 수 있도록 텍스트 분류 기능을 만들었습니다. 7주간의 엔비디아 AI 부트캠프에서 동화 데이터 전처리, GRU 베이스라인 구성, LSTM 평가와 오분류 분석을 진행했습니다.

데이터 준비와 GRU 베이스라인

동화 JSON의 문단별 줄거리 요약(plotSummaryText)을 입력으로, classification을 5개 교육영역의 정답 라벨로 사용했습니다. 중복을 제거한 뒤, 같은 책의 여러 문단이 훈련과 검증에 섞이지 않도록 GRU 노트북에서 ISBN을 기준으로 두 데이터를 나눴습니다.

Keras에서 텍스트 벡터화, 임베딩, GRU, 5개 클래스 출력층을 구성했습니다. 학습에는 EarlyStopping을 적용했고, 테스트 평가 코드에는 정확도, Macro F1, 혼동행렬, Top-2 정확도를 포함했습니다.
